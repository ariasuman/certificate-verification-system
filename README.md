# Digital Certificate Verification & Secure Storage System

A beginner-friendly Flask project for uploading certificate files, extracting readable text, storing originals privately in Amazon S3, and checking file integrity with SHA-256.

## What it does

- Accepts DOCX, PDF, PNG, JPG, and JPEG files up to 12 MB.
- Extracts DOCX paragraphs/tables, text from PDF pages, and OCR text from images or scanned PDF pages.
- Attempts to identify student name, certificate ID, course, issue date, and issuing institution from labeled text. Missing fields show **Not detected**; extracted values are automatic and should be manually confirmed.
- Uploads original bytes to S3 using server-side encryption (SSE-S3) and private object keys. The app does not set public ACLs or generate public URLs.
- Stores the expected SHA-256 digest and metadata in a separate SQLite record.
- Verifies by retrieving the existing S3 object, hashing those retrieved bytes, and comparing against the previously registered digest.
- Shows live totals on the dashboard.

**Integrity is not authenticity.** A matching hash only means that the retrieved bytes match the trusted reference hash. It does not prove who issued a certificate or that its statements are true. This check is meaningful only while the expected hash and its database record remain protected from unauthorized changes.

## Requirements

- Python 3.10 or newer (the included Render Docker image uses Python 3.12).
- An AWS account and a private S3 bucket for uploads.
- Tesseract OCR installed as an operating-system dependency for scanned PDFs and images. Text-based DOCX/PDF extraction does not need OCR.

## Run locally on Windows

1. Open PowerShell in the project folder and create/activate a virtual environment:

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   ```

2. Install Tesseract OCR for Windows (for example, the UB Mannheim Windows distribution). If it is not on `PATH`, set `TESSERACT_CMD` in `.env` to the full executable path, such as `C:\Program Files\Tesseract-OCR\tesseract.exe`.

3. Copy `.env.example` to `.env` and fill in a private bucket name, AWS region, a strong `APP_SECRET_KEY`, and a private `DEMO_ACCESS_CODE`. For local AWS credentials, prefer an AWS profile or a least-privilege IAM user. Boto3 reads the standard `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` variables if configured; never commit them.

4. Start the development server:

   ```powershell
   python app.py
   ```

5. Open `http://127.0.0.1:5000`. Enter the demo code if configured.

For Linux local development, install Tesseract with the system package manager (for Debian/Ubuntu: `sudo apt-get install tesseract-ocr`). The app normally discovers `/usr/bin/tesseract` automatically.

## AWS S3 setup

1. Create a bucket in the region used by `AWS_REGION`; keep **Block Public Access** enabled and Object Ownership set to bucket-owner-enforced.
2. Enable default bucket encryption (SSE-S3). The app also requests SSE-S3 (`AES256`) for each upload.
3. Do not add a public bucket policy. Grant the application identity only the required `s3:PutObject` and `s3:GetObject` actions on the app's bucket/prefix. The bucket's default secure policies should remain in force.
4. Set `S3_BUCKET` and `AWS_REGION` in the environment.

The application does not need `s3:ListBucket`, public ACL, or public read permissions. Protect AWS credentials and restrict access to the host and its trusted operators.

## Deploy to Render

The included `render.yaml` uses the Dockerfile. It installs the Tesseract system package and mounts a persistent disk at `/var/data` for SQLite. Render persistent disks require an eligible paid service; without a persistent disk, local SQLite data can disappear on redeploy/restart. For a robust multi-instance or production deployment, use Amazon RDS or DynamoDB instead.

1. Push this project to a private or appropriately controlled Git repository and create a Render Blueprint from it.
2. In the Render service environment settings, set `S3_BUCKET`, `AWS_REGION`, and a strong `DEMO_ACCESS_CODE`. `APP_SECRET_KEY` is generated by the Blueprint; rotate/manage it as a secret.
3. Add `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` as Render secret environment variables for a dedicated, least-privilege IAM identity. Do not put secrets in `render.yaml`, source control, build arguments, or logs. Render deployments should use an identity mechanism supported by your account if available; otherwise use rotated, restricted credentials.
4. Keep Block Public Access on for S3 and verify the service is gated by the demo code before sharing its URL.

The `Procfile` is included for platforms that build from Python directly. The included Render Blueprint selects Docker so that Tesseract is installed reproducibly.

## Deploy to Amazon EC2

1. Launch a Linux EC2 instance and attach an IAM instance role with only `s3:PutObject` and `s3:GetObject` on the certificate bucket/prefix. Do not place long-lived AWS access keys on the instance; Boto3 automatically uses the attached role.
2. Install Python, a virtual environment, and Tesseract OCR (`sudo apt-get install tesseract-ocr` on Debian/Ubuntu). Clone/deploy the project, install `requirements.txt`, and set `APP_SECRET_KEY`, `APP_ENV=production`, `DEMO_ACCESS_CODE`, `S3_BUCKET`, and `AWS_REGION` in a protected environment file outside the repository.
3. Run with Gunicorn (`gunicorn --bind 127.0.0.1:8000 app:app`) under a process supervisor such as systemd. Put a TLS-enabled reverse proxy in front of it and restrict instance security group ingress to the proxy/required administration ports.
4. Store SQLite on a persistent, access-restricted volume and back it up. For long-lived or multi-instance use, migrate the records to Amazon RDS (relational schema) or DynamoDB (key/value records) and add authentication plus per-user authorization.

Set `APP_ENV=production` so the app fails closed with a configuration page if `DEMO_ACCESS_CODE` is missing. The shared code is only a classroom demonstration gate, not account-level authentication.

## Data and security notes

- Uploaded bytes are first written into a unique temporary directory and automatically removed after processing. Only safe filenames are displayed; the S3 key contains a random server-generated UUID.
- Supported extensions and basic file structure are validated. Uploaded files are parsed as data and are never executed.
- SQLite contains private certificate metadata, S3 object keys, hashes, and verification events. Restrict the database file and backups to trusted operators. A local SQLite file is not tamper-proof against a host administrator.
- The app has no per-user accounts. Restrict the shared-code demo to intended test users and do not use it for real personal or sensitive records.
- The extracted fields and text can contain personal information. Avoid exposing the service publicly and apply a retention/deletion policy suitable for your assessment.
- For real deployments, add individual authentication/authorization, audit controls, managed durable metadata storage, recovery procedures, and review of extracted values.

## Tests

Run the tests with:

```powershell
python -m pytest -q
```

The integration-style test uses a fake S3 client to exercise upload, trusted hash registration, retrieval-based verification, and altered-object detection without AWS credentials.
